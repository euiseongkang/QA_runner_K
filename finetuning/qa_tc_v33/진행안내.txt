QA TC v0.33 파인튜닝 파일과 실행 순서
작성일: 2026-10-07

현재 상태
파일 제작과 JSON 형식 검사를 완료했다. 학습 도구 설치, 모델 다운로드,
실제 학습, 학습 모델의 평가 및 Ollama 등록은 아직 실행하지 않았다.
이 파일은 Open WebUI 지식 기반에 업로드하는 자료가 아니라 학습 도구가 읽는 데이터다.
학습 대상은 답변용 Qwen이며 embeddinggemma와 기존 RAG 지식 기반은 유지한다.

파일 구성
- before_after.txt: 사람이 읽고 검토하는 전·후 목록. 학습에 직접 넣지 않는다.
- before_after.json: 편집용 원본. 출처·추가 요구사항·전·후·분할을 포함한다.
- system_prompt.txt: 학습에서 사용한 응답 정책.
- train.jsonl: 학습용 5건. 검색어 지우기, TC16, TC17, 기본 교정, 변경 불필요.
- valid.jsonl: 학습 중 검증용 1건. TC23.
- test.jsonl: 최종 평가용 2건. TC24, TC22. 학습에 넣지 않는다.
- prepare_data.py: 편집용 원본에서 JSONL 재생성 및 형식 검사.

주의할 데이터의 출처
모든 변경 후 문구는 학습 정답 초안이며 실제 테스트 PASS 증거가 아니다.
기본 교정과 변경 불필요 사례는 사용자 요구에서 만든 합성 예시다.
TC22는 원문 전체가 없는 실행 로그로부터 재구성했다. 정확한 초기 시간 요구도
확인되지 않았으므로 사용자가 먼저 검토해야 한다. 이 사례는 평가용에만 있다.
TC16의 필터 해제와 TC23의 말줄임은 사용자의 추가 요구가 입력에 포함되어 있다.
이런 조건을 다른 TC에 자동으로 추가하도록 학습시키지 않는다.
원본의 입력값은 보존했다. 필요하면 이름을 테스트용 이름으로 전·후·근거 모두
일관되게 바꾼 뒤 학습한다.

1. 전·후 목록 검토
before_after.txt를 읽고 원하는 결과인지 확인한다.
바꾸려면 before_after.json의 before/context/after를 수정한다.
특히 TC17의 실제 패널 항목과 TC22의 정확한 초기 시간 요구를 확인한다.
최신 실행 규칙과 모순되는 정답은 학습하지 않는다.
이후 아래 명령으로 학습 파일을 다시 만든다. before_after.txt는 정적 최초 검토본이므로
원본 JSON을 편집한 이후에는 JSON의 after를 최신 정답으로 검토한다.

cd /Users/ik-lpc-084/Projects/QA_runner_K/finetuning/qa_tc_v33
python3 prepare_data.py

8건은 형식과 학습 절차를 확인하는 소규모 실험용이다. 이것만으로 품질 개선을
보장하지 않는다. 실사용 학습 전에 검토된 다양한 사례를 늘린다. 처음에는
수십~수백 건을 준비하는 작업 규모를 생각하되 필요한 수는 평가 결과로 결정한다.
동일 TC와 그 변형은 같은 분할에 두고, 학습용과 평가용을 섞지 않는다.
파일 검사는 완전 동일 원본의 중복만 찾으므로 유사 사례 누출은 직접 검토한다.

2. Mac 학습 환경 만들기
이 안내는 현재 확인한 arm64 Mac에서 MLX-LM을 사용하는 경로다.
QA 프로그램의 기존 .venv와 분리된 환경을 만든다.

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install 'mlx-lm[train]'
python -m pip freeze > requirements.lock.txt
mlx_lm.lora --help

RAM은 확인되지 않았다. 아래 명령은 1.5B 모델로 시작하는 실험 설정이며 메모리
사용량과 속도를 보장하지 않는다. 다른 모델을 쓰면 학습과 병합 모두 같은 모델로
바꿔야 한다. 최초 실행 시 Hugging Face에서 모델 파일이 다운로드된다.
Ollama의 qwen2.5:1.5b 태그 대신 학습 가능한 원본 모델 ID를 사용한다.

3. 먼저 20회 소규모 학습 실행
아래 명령을 데이터 폴더에서 실행한다. 최적의 학습 횟수가 아니라 작동 확인용이다.

mlx_lm.lora \
  --model Qwen/Qwen2.5-1.5B-Instruct \
  --train \
  --data . \
  --adapter-path adapters \
  --batch-size 1 \
  --num-layers 4 \
  --max-seq-length 4096 \
  --grad-checkpoint \
  --learning-rate 0.00001 \
  --iters 20 \
  --steps-per-eval 10 \
  --val-batches -1 \
  --save-every 10 \
  --mask-prompt

train.jsonl을 학습하고 valid.jsonl로 검증한다. adapters에 학습 결과가 저장된다.
--mask-prompt는 마지막 assistant 정답에 학습 손실을 집중한다.
버전별 옵션은 --help에서 확인한다. 메모리가 부족하면 --grad-checkpoint를 추가하거나
QLoRA용 모델로 전환하는 별도 설정을 검토한다. 임의로 모델만 바꾸고 이전 어댑터를
재사용하면 안 된다. 반복 횟수만 늘려 작은 데이터의 문구를 외우게 하지 않는다.

4. 학습에 사용하지 않은 사례로 평가
먼저 다음 명령으로 test.jsonl 평가 손실을 확인한다.

mlx_lm.lora \
  --model Qwen/Qwen2.5-1.5B-Instruct \
  --adapter-path adapters \
  --data . \
  --batch-size 1 \
  --test-batches -1 \
  --max-seq-length 4096 \
  --test

손실 수치만으로 TC 품질 통과를 판단하지 않는다. 후속 Open WebUI 비교에서는
test.jsonl의 system/user 메시지만 입력에 사용하고 assistant 정답은 넣지 않는다.
동일한 지식 기반·입력·검색 근거·생성 설정에서 원본 모델과 학습 모델을 비교한다.
RAG 검색 결과가 달라졌다면 검색 영향을 분리해 해석한다.
다음 항목을 사람이 검토하고 기존 QA 최적화 검증도 유지한다.
- 다섯 키의 JSON 응답인가?
- 입력값·대상·괄호·단위가 보존되는가?
- 클릭·입력·Enter·대기·확인 순서가 누락되지 않는가?
- 근거 없는 필터·수치·데이터 존재·기능을 추가하지 않는가?
- 설명을 반복하지 않으며 변경 불필요 판단도 가능한가?
- 실제 테스트하지 않은 PASS를 주장하지 않는가?
현재 평가 사례 2건은 시범용이며 실사용 승인에 충분한 표본이 아니다.

5. 학습 결과를 원본 모델에 병합
학습할 때 사용한 모델 ID와 동일해야 한다.

mlx_lm.fuse \
  --model Qwen/Qwen2.5-1.5B-Instruct \
  --adapter-path adapters \
  --save-path fused_model

fused_model에 병합된 모델이 저장된다. Qwen은 현재 MLX-LM의 직접 GGUF 내보내기
지원 대상에 포함되지 않으므로 mlx_lm.fuse --export-gguf를 사용하지 않는다.

6. GGUF 변환 및 Ollama 등록
아래는 병합 모델을 llama.cpp로 변환하는 경로다. 모델 파일을 외부에 공개하지 않는다.
해당 이름의 llama.cpp 폴더가 이미 있으면 중복 clone 대신 기존 위치를 사용한다.

git clone https://github.com/ggml-org/llama.cpp.git
python -m pip install -r llama.cpp/requirements.txt
python llama.cpp/convert_hf_to_gguf.py fused_model \
  --outfile qa-tc-v33-f16.gguf --outtype f16

F16 GGUF는 양자화하지 않은 모델이며 다운로드·변환·저장 공간이 추가로 필요하다.
변환기가 필요한 의존성과 모델 지원은 설치한 llama.cpp 버전으로 확인한다.
변환 오류가 있으면 그 오류를 해결한 뒤 계속하고 원본 Ollama 모델을 덮어쓰지 않는다.

아래 두 줄을 Modelfile이라는 파일로 저장한다.

FROM ./qa-tc-v33-f16.gguf
PARAMETER temperature 0

그리고 같은 폴더에서 실행한다.

ollama create qa-tc-optimizer-v33 -f Modelfile
ollama run qa-tc-optimizer-v33

어댑터 safetensors 파일 하나만 Ollama에 전달하는 방식은 이 안내에서 사용하지 않는다.
학습 채팅 템플릿과 실제 생성 프롬프트가 일치하는지 확인한다. Ollama 가져오기 후
ollama show qa-tc-optimizer-v33 --modelfile로 템플릿을 확인한다. 템플릿이 비어 있거나
응답 형식이 깨지면 해당 Qwen 템플릿 설정을 해결한 뒤 프로그램에 연결한다.

7. Open WebUI와 QA 프로그램 연결
Open WebUI가 기존과 같은 Ollama 서버를 바라보는지 확인한다.
Open WebUI에서 qa-tc-optimizer-v33 모델이 목록에 나타나는지 확인한다.
QA 프로그램에서 Open WebUI (RAG)를 선택하고 연결 확인 / 목록 갱신을 누른다.
대화용 모델을 qa-tc-optimizer-v33으로 선택한다.
QA 지식 기반과 웹 소스 지식 기반은 기존 선택을 유지한다. embeddinggemma도 유지한다.
설정을 저장하고 평가용 TC로 기존 모델과 비교한다. 개선이 확인됐을 때 실사용한다.
Open WebUI 지식 기반에 train.jsonl을 올리는 것은 파인튜닝이 아니다.
