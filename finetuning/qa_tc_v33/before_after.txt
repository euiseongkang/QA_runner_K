search_clear | 검색어 지우기 | train
출처: 사용자 검색어 지우기 스크린샷 및 X 버튼 DOM; 정답 문구는 편집 초안
상태: 정답 초안: 학습 전 사용자 검토 필요
추가 요구/근거: 사용자 제공 DOM: X 버튼은 해당 입력창에 연결된 button이며 aria-label="입력 지우기"이다. 원본 입력값과 순서를 유지한다.

변경 전
사전조건
환자 관리 목록 화면 진입 상태
테스트 절차
1. [환자명,환자등록번호,휴대전화번호] 입력창에 "강의성" 입력
2. 엔터 키 입력
3. [환자명,환자등록번호,휴대전화번호] 입력창에 "비비" 입력
4. [환자명,환자등록번호,휴대전화번호] 입력창의 [X] 버튼 클릭
5. 엔터 키 입력
예상 결과
검색어가 지워지고 검색 조건 없는 전체 목록으로 돌아온다.

변경 후
사전조건
환자 관리 목록 화면에 진입한 상태다.
테스트 절차
1. [환자명,환자등록번호,휴대전화번호] 입력창에 "강의성"을 입력한다.
2. Enter 키를 누르고 조회가 완료될 때까지 기다린다.
3. 같은 입력창에 "비비"를 입력한다.
4. 해당 입력창의 [X] 버튼을 클릭한다.
5. Enter 키를 누르고 조회가 완료될 때까지 기다린다.
예상 결과
1. 검색 입력창의 값이 비어 있다.
2. 검색어 조건이 해제된 환자 목록이 조회된다.
change_required: True
입력값과 실행 순서를 보존하고 조회 대기 및 검색 조건 해제의 관찰 기준을 구체화했습니다.

tc16 | 페이지 이동 | train
출처: 사용자 TC16 최초 및 필터 해제 추가 스크린샷; 마지막 조회 단계는 정답 초안에서 보완
상태: 정답 초안: 학습 전 사용자 검토 필요
추가 요구/근거: 사용자 추가 요구: 내 환자만 보기 상태에서는 2페이지가 없으므로 해당 체크박스를 먼저 해제한다. 이 TC는 1페이지에서 시작한다. 페이지네이션은 숫자 a 링크이며 선택 링크는 aria-current="page"로 표시된다.

변경 전
사전조건
환자 관리 목록에 2페이지 이상 데이터가 있는 상태
테스트 절차
1. 화면 하단의 [2] 버튼 클릭
2. 목록 내용 확인
예상 결과
2페이지의 환자 목록이 노출되고, 페이지네이션에서 2가 선택 상태로 표시된다.

변경 후
사전조건
환자 관리 목록 화면에 진입한 상태다.
[내 환자만 보기] 필터를 해제하면 환자 목록이 2페이지 이상 존재한다.
테스트 절차
1. [내 환자만 보기] 체크박스를 해제 상태로 설정한다.
2. 환자 목록 조회가 완료될 때까지 기다린다.
3. 체크박스가 해제되어 있고 페이지네이션의 [2] 버튼이 표시되는지 확인한다.
4. 페이지네이션의 [1] 버튼이 선택되어 있는지 확인한다.
5. 화면 하단 페이지네이션의 [2] 버튼을 클릭한다.
6. 환자 목록 조회가 완료될 때까지 기다린다.
7. [2] 버튼의 선택 상태와 환자 목록을 확인한다.
예상 결과
1. [내 환자만 보기] 체크박스가 해제 상태로 유지된다.
2. 페이지네이션의 [2] 버튼이 선택 상태로 표시된다.
3. 2페이지에 해당하는 환자 목록이 표시된다.
4. 조회 완료 후에도 [2] 버튼의 선택 상태가 유지된다.
change_required: True
사용자가 알려준 필터 해제 조건을 반영하고 페이지 선택·조회 대기·목록 확인을 분리했습니다.

상태: 정답 초안: 학습 전 사용자 검토 필요

tc23 | 긴 환자명의 목록 표시 | valid
출처: 사용자 TC23 스크린샷과 말줄임 요구; 정답 문구는 편집 초안
상태: 정답 초안: 학습 전 사용자 검토 필요
추가 요구/근거: 사용자 명시 요구: 줄바꿈이 아니라 말줄임 표시여야 한다. 긴 환자명은 목록 높이와 정렬에 영향을 주면 안 된다. 긴 이름 데이터 존재는 실행 전에 확인할 준비 조건이지 현재 존재한다고 확인된 사실이 아니다.

변경 전
사전조건
환자 관리 목록 화면 진입 상태
테스트 절차
1. 화면의 [환자 관리] 버튼 클릭
2. 환자명이 긴 환자의 행을 확인
예상 결과
긴 환자명이 잘리거나 줄바꿈되어 표시되며, 다른 컬럼 정렬이 깨지지 않는다.

변경 후
사전조건
환자 관리 목록 화면에 진입한 상태다.
조회할 목록에 환자명 표시 영역의 너비를 초과하는 환자와 비교할 일반 환자가 존재해야 한다.
테스트 절차
1. 화면의 [환자 관리] 버튼을 클릭한다.
2. 환자 목록 조회가 완료될 때까지 기다린다.
3. 표시 영역의 너비를 초과하는 환자명의 셀을 확인한다.
4. 환자명이 한 줄의 말줄임으로 표시되는지 확인한다.
5. 해당 행의 높이를 일반 환자 행과 비교한다.
6. 해당 행의 다른 셀과 열 헤더의 정렬을 확인한다.
예상 결과
1. 표시 영역을 초과하는 환자명은 한 줄의 말줄임으로 표시된다.
2. 긴 환자명으로 인해 행 높이가 증가하지 않는다.
3. 다른 열의 위치와 정렬이 유지된다.
4. 환자명이 셀 밖으로 넘치지 않는다.
change_required: True
사용자가 지정한 말줄임 요구를 반영하고 행 높이·열 정렬·셀 넘침의 관찰 기준을 구체화했습니다.
